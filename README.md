# 隐序 · 私人空间

一个供个人使用的记录与资料工作台。笔记、待办、项目、日历、网页和附件放在同一个可检索的空间，内容按登录账户独立保存。当前版本为 0.5.0；完善草稿关闭语义、跨窗口设置、专题备份、命令面板和可选回收站保留期。

## 技术与环境

- Node.js 22.13 以上（开发验证使用 Node.js 24）。
- React 19 + TypeScript + Vinext/Vite。
- Cloudflare Workers 执行服务端代码；D1 保存结构化数据，R2 保存附件。
- Sites 平台负责站点入口访问范围与 ChatGPT 登录。应用 API 额外检查每条记录的账户归属；发布更新保留平台当前访问设置。
- Git、npm 和 Windows 自带 `tar.exe` 支持打包流程。

`.openai/hosting.json` 记录此网站的站点身份和 `DB` / `BUCKET` 绑定；复用现有 `project_id`，不要再次创建站点。

## 安装、构建与本地运行

在本项目目录执行：

```powershell
npm run install:ci
npm run db:generate
npm run build
```

首次准备本地数据库时，按顺序执行已生成的迁移。已有本地库只执行尚未应用的迁移。已执行的迁移不要重复运行；之后的修改应添加新迁移。

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_far_stryfe.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_nebulous_madrox.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_optimal_tempest.sql
npm run dev -- --port 5181 --host 127.0.0.1
```

打开终端给出的本地地址。开发预览通过 starter 的回环地址模拟登录，显示 `Seedy`，与线上账户及线上数据库隔离。这个模拟登录只用于本地开发，构建产物不包含此登录实现。开发服务只绑定 `127.0.0.1`，不要通过反向代理公开开发预览。

构建后的本地 Worker 可使用 `npm start` 运行，但它不模拟登录；普通使用和界面检查建议使用上述开发命令。

## 使用说明

1. 主页可直接随手记到收集箱，`Ctrl/Cmd + Enter` 保存；“新建”选择模块。编辑收集箱记录时可通过“整理为”转换内容类型。
2. 搜索框跨模块搜索标题、正文与标签；`Ctrl/Cmd + K` 聚焦搜索。
3. 每次保存内容都会生成一个版本；重新打开内容可查看最近 30 个历史版本，载入旧版后需再次保存才生效。
4. “移入回收站”保留内容和附件；可恢复。彻底删除需要额外确认，并删除该记录的版本历史及附件。
5. 文件和照片最多每个 25 MB。相册支持经文件头校验的 JPG、PNG、GIF 和 WebP；其他文件通过文件库下载。
6. JSON 备份包含正常、归档和回收站记录、专题、设置和附件索引。ZIP 备份进一步包含附件原文件、SHA-256 校验、历史及操作日志归档（history.json/activity.json）。导出在当前浏览器完成，不上传第三方。
7. 恢复支持 v1/v2 JSON、v3 ZIP；先检查全部记录和附件摘要，再确认追加副本，重新映射专题、项目和附件关联。ZIP 恢复回收站附件及其回收状态。历史和操作日志作为归档保留，不回写；偏好设置不会覆盖。重复恢复会产生副本，失败前已经完成的内容会保留并报告数量。
8. JSON 最大 10 MB，每次恢复最多 1,000 条；ZIP 输入最大 110 MB，附件总量最多 100 MB，解压前限制条目和总大小。备份生成不是数据库事务快照，操作备份时尽量暂停其他窗口的编辑。
9. 列表每页 200 条，支持加载更多，批量操作最多 100 条。搜索、标签、类型、状态、日期、专题、优先级、阅读状态和文件类型由服务器筛选。支持更新时间、创建时间、标题和日期排序；所有排序均保留置顶。
10. 账本按全部筛选结果聚合，以整数分计算；CSV 同样导出全部匹配记录，处理公式注入。日历读取六周范围全部分页，切换月份后再编辑不会跳回当前月。
11. 项目内待办立即保存，任务子清单随编辑器保存。归档再取消归档保留待办原来的完成状态；移入回收站后提供短时撤销。
12. 非附件记录在停止输入约 0.9 秒后保存服务端草稿。草稿有独立版本；重新打开需选择恢复或放弃，正式保存后清除自己的草稿。保存失败会显示提示，网络中断前未确认保存的内容不能保证跨设备恢复。每账户最多 50 份草稿，可在设置继续编辑。
13. 设置中可对标签改名、合并或移除，作用于全部记录（含归档和回收站），分批执行、保存历史、增加版本。失败后可重试剩余部分，正文和附件保留。
14. 每账户最多 10,000 条内容、1 GB 已登记附件，回收站仍占配额。上传在事务内检查总量，失败会清理刚上传的对象。每条记录保留最近 100 份快照，界面展示最近 30 份；操作日志保留最近 10,000 条，在日常写入时清理，无独立后台定时器。

## 私密访问与维护边界

站点入口的公开或私密范围由 Sites 设置。2026-11-04 更新前核对的平台状态为公开，本次沿用该设置；页面和内容 API 仍要求登录，每个 API 检查用户 ID 和记录所有权。其他登录账户不会因此读到你的记录。附件没有公开的 R2 链接，下载经过相同的身份及归属检查。需要限制站点入口时，应在平台访问设置中另行修改；不要用文案代替权限设置。

私密访问控制不等同于端到端加密；服务端需要处理明文以完成搜索、编辑和导出。此版没有自建密码认证、支付、外部 AI 调用或第三方分析脚本。

所有真实记录使用 D1/R2 持久化。浏览器不使用 localStorage 保存业务记录。`.wrangler/`、`.env*`、本地测试资料和 `outputs/` 已忽略，不能提交到源代码仓库。线上数据不会由本地迁移和测试创建或覆盖。

## 工程检查与信任边界

- `npm run test:unit` 验证输入、查询游标、可移植导出与备份校验；`npm run test:integration` 在本地预览验证 HTTP、所有权、附件、配额、分页和历史保留。
- `npm run typecheck`、`npm run lint`、`npm run format:check` 提供持续检查；`npm run format` 格式化应用与维护代码。保留 Rules of Hooks 和依赖检查；不启用 React Compiler 可选的 set-state-in-effect 优化规则。受保护图片不经过 Next 图片优化代理。
- GitHub Actions 在 main 推送和 PR 执行安装、格式、类型、Lint、单元测试、构建、本地独立 D1 迁移及集成测试；不需要生产密钥，不自动部署或操作线上数据。是否在 GitHub 上通过，以实际 Actions 结果为准。
- 身份来自 Sites 网关注入的用户头，代码依赖平台清除外部伪造头并阻断绕过网关的入口。本仓库无法独立核验平台控制的 workers.dev 配置；脱离 Sites 自行部署时必须关闭直连域名或增加可信身份验证，不能直接暴露这个 Worker。
- HTML CSP 限制资源来源，允许 ChatGPT/OpenAI 自有嵌入页面及 ZIP 使用的本机 Worker，阻止任意第三方嵌入。文件响应单独保持 sandbox。日志记录服务端错误栈，接口仍返回通用错误。
- `.openai/hosting.json` 是部署身份与绑定声明，不是访问密钥；更新时必须保留。用户记录、附件、开发身份和临时输出均不入库。

完整功能清单和审查处理结果见 `docs/FEATURES.md`、`docs/REVIEW.md`、`docs/REVIEW-ROUND-2.md` 和第三轮整改 `docs/REVIEW-ROUND-3-RESOLUTION.md`。

## 常见问题

**页面显示 Seedy？** 这是本地预览身份，线上通过平台登录后会显示你的实际账户信息。

**提示记录在其他窗口更新？** 说明此窗口拿到的是旧版本。保留尚未保存的文字，刷新并查看最新内容后重新修改。接口返回 409，不会覆盖另一窗口的新内容。

**记录删除后提示附件待清理？** 元数据已删除，待删除对象键保存在持久化队列。打开“空间设置 → 附件删除重试”，直到队列清空。

**筛选后结果比当前页更多？** 筛选和数量统计由服务端处理全部匹配记录，列表每次读取 200 条。点击“加载更多”继续读取。

**更改了数据表？** 修改 `db/schema.ts`，运行 `npm run db:generate`，检查新 SQL，再分别应用本地迁移和走正常线上发布。已经应用的迁移及其元数据保持不变。

## 0.4.0 行为补充

- 文件库与内容附件复用同一上传队列；仅在整批排队任务结束后刷新列表，成功项不会随失败重试再次上传。编辑器中的未完成上传会在关闭窗口时取消，已成功附件保留。
- 普通模块内的无筛选编辑局部替换返回行；可能影响筛选、排序成员或汇总的变化仍重新读取服务器，避免估算造成错误。
- 草稿预览包含完整时间、正式内容和正文对照；基于较旧正式版本的草稿需二次确认。恢复只填入编辑器，正式保存仍检查版本。
- 主页“那年今日”只显示往年同一天的有效日记；没有匹配记录时不占空卡片。账本趋势补齐连续六个月份，空月按零显示。Markdown 任务列表为只读预览。
- 数据获取、弹窗和导航分离到 app/hooks/use-space-data.ts、app/components/workspace-dialogs.tsx、workspace-sidebar.tsx。

## 0.5.0 使用补充

- `Ctrl / ⌘ + K` 或顶部命令按钮打开搜索与命令，支持跨模块查找、切换模块、进入专题和新建内容，使用方向键与 Enter 操作。记录搜索默认排除归档和回收站。
- 关闭有修改的文字编辑器时，明确选择“保留草稿并关闭 / 彻底丢弃 / 继续编辑”。保留失败不会关闭；丢弃先停止自动保存并等待正在进行的请求，再按版本删除草稿，失败时保留编辑窗口。关闭时若还有附件上传，会明确提示取消未完成部分；保存内容前需等待或取消上传。
- 设置表单会同步未修改的后台偏好；已有修改时提示冲突，可载入最新设置或只合并本窗口改过的字段。保存带基准值并执行数据库条件更新，防止另一窗口的新设置被覆盖；“检查最新设置”不会重建表单。
- 专题页可导出 JSON 或附件 ZIP。导出包含正常、归档、回收站记录及关联附件，只归档该专题记录的历史和操作日志，不带整个账户的设置或其他专题。既有 ZIP 大小、哈希和导入校验继续适用；跨专题项目引用在恢复时仅映射包内目标。
- 回收站保留期默认“永不自动清理”；可选择 30 / 90 天，开启前还需勾选不可恢复提示。保存内容时惰性清理到期项，每次最多 20 条，旧记录的恢复先执行。没有新增后台任务。关闭保留期后停止后续自动清理；已彻底删除的内容不能找回。请在开启前自行备份。
- 依赖已升级到修复高危通告的兼容版本，CI 增加 `npm audit --audit-level=high`。本次生产依赖审计为 0，高危/严重通告为 0；开发工具链仍有 24 项中危通告，详见第三轮整改记录，不使用 `--force` 降级框架或隐藏告警。
- 构建配置声明关闭 `workers.dev` / 预览域名，Worker 对直接 `workers.dev` URL 或 Host 返回 403。平台身份头仍依赖可信网关，应用侧防线不能代替托管平台对全部入口和头清洗策略的证明。
