# 0.6.0 日常使用增强

日期：2026-11-04（Asia/Shanghai）。根据 IDEAS.md 选择能沿用当前模型、无需外部服务配置、可完成验证的一组功能；想法池本身保留，不代表其中全部方向已承诺实现。

## 已实现

| 能力           | 行为与边界                                                                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 近期提醒       | 日程选择倒数日/续费，联系人输入公历生日；主页统一展示，点击打开原记录。生日年年滚动，平年 02-29 按 02-28；过期续费仍提示。无后台推送、自动扣款或自动记账。                  |
| 快捷收藏与记录 | 设置提供收藏书签代码与快捷笔记入口；/capture 负责正常登录衔接，片段只接受限定种类/长度和 HTTP/HTTPS。先核对、再进入编辑器、最后正式保存。不会抓页面正文或隐式创建正式记录。 |
| 独立快捷草稿   | 每次带入使用 new-kind-UUID，保留/丢弃/继续编辑语义一致；设置能找回该草稿。不会覆盖普通新建草稿。                                                                            |
| 正文粘贴图片   | 真实剪贴板图片经共享上传队列入相册，成功后追加受保护的图片引用并显示预览。支持 PNG/JPG/GIF/WebP，单个上限 25 MB；新建笔记也可先贴图再保存。关闭保留已上传图片，失败可重试。 |
| 图片备份恢复   | 专题 ZIP 补齐正文引用但尚未关联专题的图片；恢复为新图片 ID 后重写正文。JSON 不含原图时显示缺图说明。单条 Markdown 不构成离线图片包。                                        |
| 回收站剩余期限 | 按实际 deletedAt 和已保存保留期显示剩余天数与到期时间；到期不代表正有后台计时删除。默认仍关闭。                                                                             |
| 重模块按需加载 | 编辑器、日历、设置、活动、看板、账本独立加载，专题备份按按钮操作载入。没有新增依赖。                                                                                        |

## 验证证据

- 116 项单元测试，包含日期/闰日/跨年/夏令时、快捷协议安全、图片 URL 白名单、图片恢复 ID 和回收站版本号顺序等。
- 254 项集成断言：原 227 项与新增日常功能 27 项；新增检查提醒突破首屏分页、账户/状态隔离、非法输入、独立草稿键、真实照片 MIME/下载身份，以及未登录可访问的无账户数据快捷中转页面。
- 浏览器真实创建倒数日，主页显示 14 天；真实剪贴板粘贴 PNG，上传后预览可见并正式保存。
- 浏览器导出 13 条内容、1 个专题、1 个图片附件的 ZIP，其中图片原本不属于该专题。确认追加恢复后，新笔记引用新图片 ID，原图与恢复图 SHA-256 相同、均可按账户下载。
- 快捷网页的标题和含 & 参数的网址完整带入，核对后保存；手机快捷笔记未再次修改也可保留为独立草稿，在设置恢复并正式保存。
- 本地暂开 30 天保留期核对到期提示，确认无无关到期内容后只读取页面，随后恢复原设置 0；线上保留期未修改。
- 手机 390 像素视口，提醒卡片及设置无横向溢出，浏览器运行错误列表为空。所有演示数据仅在本地，未上传到线上。
- 0.5.0 发布包的 Workspace 构建块为 246,413 字节（gzip 75,254）；0.6.0 拆分后的块约 80 KB（gzip 约 26 KB）。这是构建分块比较，不代表整个首屏流量或生产 LCP 已测量。

最终格式、类型、lint、单元、集成、构建、GitHub CI 与发布状态以实际交付结果为准，不把文件存在当作已发布。

## 留待后续的方向

邮件收集需要独立收件域名/路由、发件认证和写入身份；加密备份需先确定通用加密 ZIP 与专用加密包的格式/恢复兼容性；双向链接、习惯表、周期任务和公开分享涉及新的状态或权限模型，未混入本版。当前沿用已有单元/HTTP 自动检查和真实浏览器验收，尚未新增独立 Playwright CI 项目。

认证仍依赖 Sites 可信网关，入口与头清洗的托管侧证明未因本版功能增加而消失。此版不改变平台访问范围，也不把日期提示说成站外通知服务。
