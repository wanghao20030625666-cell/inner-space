# 隐序后续想法池

版本：基于 0.5.0。日期：2026-11-04。目的：汇总产品、技术、体验和工程方面的候选方向，供后续按价值/成本挑选，不代表承诺实现。

## 一、最值得优先考虑（价值高、成本相对可控）

| 优先级 | 想法                        | 价值                                     | 成本/前提                                                          |
| ------ | --------------------------- | ---------------------------------------- | ------------------------------------------------------------------ |
| P0     | 邮件转收集箱                | 任何设备发邮件即可记录，解决临时输入痛点 | Cloudflare Email Routing + Workers email handler；需域名和地址鉴权 |
| P0     | 倒数日/生日/订阅续费提醒    | 让主页每天打开都有实际用途               | 复用 event/contact/meta；本地日期计算即可                          |
| P0     | 加密 ZIP 备份               | 备份可安全放入网盘，补齐数据安全链路     | 浏览器 WebCrypto；明确密码不可找回                                 |
| P0     | 按专题/模块的只读导出包     | 迁移、分享、长期归档更方便               | 复用现有 backup/ZIP 管线                                           |
| P0     | 核心流程 Playwright E2E     | 防止功能快速迭代后回归                   | 本地预览 + 合成数据，不接触线上                                    |
| P1     | 习惯打卡与连续天数          | 增强日常使用频率                         | 新 kind 或独立打卡表；热力图可用 CSS 实现                          |

## 二、功能想法：收集与输入

1. **Bookmarklet 一键收藏当前网页**：无需扩展，书签栏点击后带入 URL 和页面标题；成本极低。
2. **快速记录 URL**：如 `/#quick=note&text=...`，配合手机桌面快捷方式、快捷指令或浏览器自定义搜索。
3. **URL 规则自动整理**：按域名自动添加标签/归入专题，例如 GitHub 链接自动标记“技术”；规则必须可见、可修改，不做隐式 AI 分类。
4. **重复收藏检测**：新建网页收藏时提示已有同 URL 记录，可选择打开原记录。
5. **自然语言日期**：待办输入“明天下午 3 点”“每周一”时提供候选解析，必须由用户确认结果；不要默默创建错误日期。
6. **全局拖拽输入**：把文本/文件拖到主页，根据内容类型提供“存为笔记/收藏/文件”选择。
7. **移动端系统分享入口**：PWA Share Target 或 URL Scheme，让其他 App 的分享直接进入收集箱。

## 三、功能想法：笔记与知识管理

1. **笔记模板**：会议纪要、周记、复盘、读书笔记；模板作为普通记录管理，新建时复制内容，不需要新表。
2. **双向链接与反向引用**：`[[笔记标题]]`，显示“被哪些记录引用”；标题改名时应提示更新引用或采用稳定 ID。
3. **全局时间线**：笔记、日记、待办、收藏、日程按时间混排，可筛选类型；数据已有，主要是视图工作。
4. **阅读模式**：隐藏编辑控件和侧栏，适合长文阅读；配套打印样式。
5. **Markdown 表格与代码块复制按钮**：扩展现有安全子集，不引入原始 HTML 执行。
6. **字数与阅读时长**：编辑器已有字数，可增加预计阅读时间和写作统计。
7. **学习卡片/间隔复习**：把笔记中的问答转为复习卡片；属于独立复杂功能，应单独评估，不与普通笔记保存耦合。
8. **随机回顾**：随机打开一条旧笔记/照片/日记，形成低成本“回忆漫游”。
9. **年度回顾**：按年汇总字数、照片、完成待办、收支等，生成只读报告。

## 四、功能想法：待办、项目与时间管理

1. **习惯打卡 + 热力图**：每日打卡、连续天数、年度视图；建议独立打卡数据，不强行复用 journal。
2. **番茄钟与专注记录**：关联待办，记录专注时长；可离线工作，结束后再同步。
3. **时间块日历**：日程支持时间轴日视图/周视图，适合安排学习或工作块。
4. **待办投入与估算**：预估时长/实际时长，项目页显示投入汇总。
5. **周期性待办**：完成后按规则生成下一实例；需处理时区、跳过、暂停、幂等和回收站边界。
6. **OKR/年度目标**：目标关联项目和待办，按周期复盘；可先用专题模板验证使用频率。
7. **会议记录联动**：参会人关联联系人，行动项一键转待办，纪要作为笔记保存。

## 五、功能想法：生活、财务与健康

1. **倒数日**：考试、纪念日、旅行等倒计时；主页最多显示近期几项。
2. **生日与联系纪念**：联系人增加生日/重要日期，主页显示未来 30 天提醒。
3. **订阅管理**：订阅价格、周期、下次扣款、续费提醒；可关联账本和倒数日。
4. **分类预算**：按自然月设置餐饮/交通等预算，账本显示进度和超支；现有分类聚合可直接复用。
5. **固定周期收支**：工资、房租等自动生成；惰性补录即可，不必依赖 Cron，但必须幂等。
6. **报销状态**：待报销/已报销及发票附件，利用现有附件关联。
7. **物品与库存**：存放位置、购买日期、保修到期、食品保质期提醒；可先以专题模板试用。
8. **书籍/影视记录**：想看/在看/看过、评分、短评；新 kind 或书签扩展，注意搜索与导出兼容。
9. **健康数值记录**：体重、运动时长等简单序列和趋势图；明确不作为医疗建议，不记录高度敏感医疗信息。
10. **情绪/感恩日记**：心情标签和月度分布，作为可选日记字段，不做诊断性描述。

## 六、分享、导出与数据开放

1. **加密 ZIP 备份**：密码派生密钥、AES-GCM、明确随机盐和版本格式；忘记密码不可恢复，必须醒目提示。
2. **Obsidian 友好导出**：Markdown 目录 + attachments 相对链接，便于迁移到本地知识库。
3. **只读静态 HTML 导出**：专题或年度记录导出为可离线浏览的 HTML 包，不执行原始 HTML。
4. **打印/PDF 友好样式**：笔记、账本、日历的打印 CSS；无需服务端生成 PDF。
5. **导入外部数据**：按需支持 Obsidian/Markdown、通用 CSV 账本、vCard、iCal；每种格式单独做字段映射和测试。
6. **个人 API Token**：只读或限定写入范围，供快捷指令和脚本使用；需要过期、撤销、权限范围、访问日志，优先级低于内部功能。
7. **只读分享链接**：单条内容可选分享，必须默认关闭、带过期和撤销；会改变私密边界，需单独评审。

## 七、移动端与交互体验

1. **移动端底部导航**：主页/收集箱/待办/新建，减少侧栏抽屉操作。
2. **下拉刷新与滑动操作**：滑动完成待办、归档卡片；必须同时保留按钮入口。
3. **主页模块排序**：随手记、待办、日程、趋势等模块自定义顺序，存 settings。
4. **减少动画支持**：遵循 `prefers-reduced-motion`，检查上传、弹窗和图表动画。
5. **骨架屏**：列表、主页指标和编辑器历史使用骨架屏替代部分 spinner。
6. **完整快捷键层**：在命令面板基础上增加 `g n` 等导航序列，提供可发现帮助。
7. **触控目标与对比度审计**：按钮至少约 44px，深浅主题文字对比符合可读性要求。
8. **空状态与新手引导**：按账户是否已有内容展示不同示例，避免永久显示通用空文案。

## 八、架构、性能与平台能力

1. **首屏代码分割**：编辑器、日历、设置、备份等按需加载；先用构建报告确定最大 chunk。
2. **长列表虚拟化**：200 条卡片 DOM 已有成本；先测量滚动性能，再决定是否引入虚拟列表。
3. **图片缩略图**：相册列表不加载原图；可上传时生成缩略图或使用托管图像服务，需评估 Workers 图像处理能力和费用。
4. **EXIF 拍摄时间**：照片可选提取拍摄时间用于排序；注意隐私，默认不保留 GPS。
5. **偏好/专题短缓存**：仅在同一请求或短 TTL 内缓存，避免跨账户缓存和设置更新延迟。
6. **D1 Time Travel 评估**：作为误删/误写的额外恢复手段，但不能替代导出备份。
7. **Cron 使用候选**：自动备份、死链检查、周期任务；每项单独设计失败重试和通知，不把 Cron 当成默认答案。
8. **邮件收集的安全边界**：验证发件人、限制正文/附件大小、防止伪造和垃圾邮件灌入配额。
9. **请求体与导出内存基准**：100 MB ZIP 在浏览器中的峰值内存需要测量，必要时提前分批。

## 九、测试、质量与运维

1. **Playwright 核心 E2E**：新建→编辑→冲突→历史→回收站→恢复→彻底删除→备份恢复。
2. **视觉回归**：深浅主题、390px 移动端、命令面板、编辑器弹窗截图对比。
3. **性能预算**：首屏 JS、LCP、交互响应设阈值，CI 超阈值报警；先看基线再定数字。
4. **备份兼容矩阵**：v1/v2/v3 JSON/ZIP、含附件/缺附件、回收站、跨项目关联的固定样本测试。
5. **随机输入测试**：recordInput、备份解析、Markdown、游标和日期解析使用随机/畸形输入验证不崩溃。
6. **覆盖率报告**：输出 vitest coverage，重点覆盖领域逻辑；不为了覆盖率写无意义测试。
7. **CI 定期运行**：每周运行测试和 npm audit，避免长期不发版时漏洞不可见。
8. **站点可用性监控**：外部 uptime 检查只访问健康端点，不把私有页面内容交给第三方。
9. **预览环境**：若平台支持，PR 预览部署；必须与生产 D1/R2 隔离。
10. **故障演练**：本地模拟 R2 删除失败、D1 冲突、备份中断、草稿删除失败，验证恢复路径。

## 十、文档与项目治理

1. **CHANGELOG.md**：按版本记录用户可见变化，审查记录与更新日志分开。
2. **用户备份指南**：推荐导出频率、加密方式、保存位置和恢复演练，不只描述按钮。
3. **ADR 架构决策记录**：保留 FTS5 不迁移、身份信任边界、备份追加恢复等决策的原因。
4. **SECURITY.md**：说明报告渠道、认证信任前提、无 E2E 加密的边界。
5. **隐私说明**：列出 D1/R2/平台登录及所有外部依赖，明确没有哪些第三方分析。
6. **截图与短视频**：README 展示主页、命令面板、备份恢复，便于以后分享或交接。
7. **功能模板库**：旅行、装修、备考、婚礼等专题模板，验证产品是否覆盖真实生活流程。

## 十一、明确不建议当前做

- **密码/支付卡管理**：没有端到端加密，不应把界面标记包装成安全保管。
- **多人实时协同**：CRDT/在线状态/权限模型复杂度与个人定位不符。
- **默认开启 AI 读取内容**：隐私、成本、提示注入和误判风险需要单独评审。
- **公开社交/评论**：与私人空间定位冲突。
- **仅为技术升级而迁移 FTS/新框架**：先用真实数据证明必要，保留回滚路径。
- **把自动清理、自动备份、分享链接默认打开**：涉及不可逆删除或私密边界的功能均应默认关闭。

## 十二、建议的三阶段组合

### 阶段 1：低成本日常价值

倒数日、生日提醒、Bookmarklet、剪贴板贴图、回收站倒计时、核心 E2E。

### 阶段 2：形成产品特色

邮件转收集箱、习惯打卡、笔记双链、加密备份、移动端底部导航。

### 阶段 3：谨慎扩展边界

个人 API、只读分享、外部数据导入、Cron 自动备份；每项先做隐私/安全评审。

所有实现继续遵循现有验收：`format:check`、`typecheck`、`lint`、`test:unit`、`build`、本地 `test:integration` 全绿；涉及删除、身份、分享和备份格式的改动必须增加对应回归测试。
