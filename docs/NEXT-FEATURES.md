# 私人生活工作台：非笔记功能扩展评估

日期：2026-11-05。根据用户希望扩展到笔记之外的要求，结合当前记录、待办、日历、账本、文件和联系人能力评估。以下均是候选方案，本轮仅修复既有问题，没有将候选功能写进产品已实现清单。

## 优先考虑

| 顺序 | 方向           | 完整使用流程                                                                      | 可复用部分                               | 工作量与边界                                                                                                                    |
| ---- | -------------- | --------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 家庭物品与保修 | 登记设备/家具 → 保存购买凭证与说明书 → 查看保修到期 → 记录维修/处置               | 附件、搜索、标签、到期提示、账本金额关联 | 中。新增清楚的物品模型/入口，补所有权、编辑、删除、备份恢复、筛选与导出；不把一份笔记换标题就称为物品管理。第一版不做折旧计算。 |
| 2    | 订阅与续费管理 | 登记会员/域名/云盘 → 显示下一次日期与预计费用 → 手动确认续费或停用 → 更新下一日期 | 已有续费提醒、日历、账本                 | 中。区分预计年成本与实际支出，避免重复生成账目；第一版由用户确认，不自动扣费或补录。周期和停用规则要完整。                      |
| 3    | 到期事务中心   | 登记证件/合同/保险等事项名称和到期日 → 站内提醒 → 创建办理待办 → 保存新版本材料   | 文件、待办、日期提醒、专题               | 中。优先名称、类别、期限、办理说明；不默认要求证件号码或扫描件。需合并相同事项的提醒，说明仅站内提示。                          |
| 4    | 行程与旅行筹备 | 建行程 → 安排每日日程 → 生成出发清单 → 整理票据资料/联系人 → 对照预算和实际支出   | 专题、日历、项目待办、文件、联系人、账本 | 中至大。先做可选择模板及关联面板；预算与账本实际值分开，不接预订、支付或位置追踪。需要清楚的关联入口，不复制同一条数据。        |

建议先实施“家庭物品与保修”，其次补足已有“订阅续费”的管理闭环。前者新增明确的生活用途，后者能直接沿用已有日期与账本能力。若实际使用以出行为主，可将旅行筹备提前。

## 第二梯队

- **借出与归还**：物品关联联系人、借出日期、约定归还日期、实际归还与状态记录。适合作为物品管理的下一步，避免一开始增加复杂审批。
- **愿望与采购清单**：记录想买的东西、用途、链接、手动估价与优先级，购买后转入物品并可关联实际账目。不做自动比价或下单，预计金额不能混入实际支出。
- **家庭维护记录**：设备清洁、车辆保养、房屋维护的完成历史、凭证与下一次建议日期。先支持明确的单次安排；真正周期生成需要单独解决幂等、暂停、跳过和历史。
- **阅读/观影清单**：想看、进行中、完成、个人评价与参考链接。可先用明确的清单模型，避免为每类内容复制整套 CRUD 或抓取有版权的正文。

## 本阶段不建议扩展

多人协作与公开分享、密码保险箱、投资交易/自动记账、医疗诊断、默认 AI 扫描个人文件、系统级远程控制等，会引入与当前私人工作台明显不同的权限、密钥、准确性或运维要求。它们不属于简单添加一个板块的工作量。

## 共同完成标准

每个新模块必须同时具备创建/修改、列表与检索、必要的状态流转、跨模块跳转、账户隔离、历史/回收与文件处理、导出/备份/恢复兼容、移动端和失败提示。新增记录类型需更新 API 枚举校验、编辑器、统计、配额、全局搜索与导出，而不是只新增导航按钮。

原有布局可延续，允许按实际用途增加模块，但不把所有功能塞进主页。优先让“记录一件生活事务 → 找回资料 → 处理 → 完成”形成闭环。
