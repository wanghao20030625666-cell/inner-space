# 架构与数据生命周期

## 0.6.2 交互状态保护

CalendarView 接收与父列表相同的标签参数；完整可见日期范围的取数结果同时用于月历、当日议程与当月 ICS，错误时禁止导出。项目列表通过受保护 lite 接口按游标追加，每页 200，完成数来自完整项目聚合；刷新重新读取已展开范围，循环游标报错。项目编辑器保留自身状态和草稿钩子，只切换当前可见编辑器为待办详情，返回后重载项目列表，不同时挂载两套 Modal。父项目上传未完成时禁止打开任务，避免切换导致上传组件被卸载。

设置 reducer 上移至工作区，会话中切换模块不再丢弃脏表单；远端 receive、冲突和显式 merge/save 语义保留。dirty 时注册 beforeunload，清理时移除；不把未保存设置持久化，也不自动提交保留期。用户可显式放弃，回到最新已知远端设置。

## 0.6.1 模块查询与批量删除

完整空间响应通过共用函数组装列表、侧栏、账本、项目和主页投影。模块入口使用 `lite=1&context=module`：普通类型列表执行 7 条查询（列表与总数 2，侧栏元数据 5）；可能包含项目的混合列表或项目模块补 1 条全量项目进度，账本模块补 3 条受当前筛选约束的金额聚合。原精简分页维持 2 条查询，指定 project 的任务分页补 1 条项目进度。完整主页为 18 条查询。数字来自代码查询路径计数，不是生产延迟或 SQL 扫描量的测量。

`GET /api/trash` 是账户级只读快照，最多 10,000 条 id/version，对齐空间记录配额。客户端确认该固定快照，每批最多 10 条调用 `POST /api/trash`；不会把后续新增垃圾纳入操作。服务端 Zod 验证 UUID、版本、数量、重复 ID，再按 owner 读取并构造原有版本保护删除事务。已恢复、版本已变化或不可见的记录分别跳过；同一事务移除记录草稿、历史、写入审计并将实际文件键放入清理队列。10 张图片最多 51 条事务语句。网络返回不明确时，客户端停止后续批次并报告未确认，不自动重试。删除文字记录不级联删除独立的文件记录。

上传收起仅改变展示状态，队列控制器持续挂载，取消和组件卸载生命周期保持独立。专题重名确认是客户端易用性提示，按当前已载入专题名的 trim/NFKC/大小写比较，不是数据库唯一性或并发锁；允许备份恢复中的同名专题。没有数据迁移或新增依赖。

## 设计

采用模块化单体：浏览器工作台负责交互，独立 API 负责认证、授权和校验，D1 与 R2 分别负责记录和附件。个人业务共用一套记录模型，避免每个模块重复实现收藏、搜索、删除和版本管理。

模块目录 `app/lib/catalog.ts` 决定导航名称、图标与描述；数据类型与校验集中在 `app/lib/model.ts`。各页面复用编辑器，但保留对应的输入字段，如网页地址、收支金额或联系人信息。

## 数据表

| 表           | 用途                                                        |
| ------------ | ----------------------------------------------------------- |
| records      | 内容记录，以 owner + kind 查询，包含当前版本号和软删除时间  |
| collections  | 按 owner 保存专题名称、颜色；records.collection_id 引用专题 |
| revisions    | 更新前的完整快照，按 owner + record_id 检索                 |
| audit        | 内容创建、修改、软删除、恢复和彻底删除的操作记录            |
| settings     | 按 owner 存储空间偏好                                       |
| blob_cleanup | 彻底删除后的附件清理任务，失败可重试                        |

用户身份只取平台注入的稳定 ID，不接受请求体中的 owner。每个查询、更新、版本读取和附件访问都按此 ID 授权。电子邮箱只用于界面显示。

## 写入与冲突

创建内容与对应日志在 D1 batch 事务中提交。更新要求客户端传入读取时的 version；事务先按旧版条件存快照，再按相同条件更新，最后为成功写入添加日志。没有更新到行时返回 409。旧窗口不能静默覆盖新内容。

写入入口校验来源、标题、正文长度、标签数量、日期和模块字段。网页链接限制为 HTTP/HTTPS。文本通过 React 文本节点显示，Markdown 预览不执行原始 HTML。

专题关联与新设置的项目关联分别校验 owner。收集箱转换只允许转为笔记、日记、待办和网页收藏，保留记录 ID 并写入转换前历史。移除专题在同一事务中解除记录关联、递增版本并移除专题；旧编辑器返回 409。已有待办关联的项目被删除后，待办仍可编辑，新的关联不能指向已删除项目。

批量操作复用逐条带 version 的 PATCH，不是跨记录事务。界面报告成功和失败数量。项目内待办立即保存；进度聚合排除归档与回收站待办。

## 删除与附件

软删除只写 deleted_at，不移除 R2 对象；普通列表和下载都会拒绝回收站文件。恢复会生成下一版本。

彻底删除只允许回收站记录。对版本号再次校验后，将附件键加入清理队列、删除版本历史及当前记录，在同一 D1 事务中提交。随后尝试 R2 删除；失败时保留队列键供重试。清理仅处理文件/照片类型，而且对象键必须匹配当前 owner/record-id。用户可在设置页重试，不需要恢复已删除的元数据。

上传文件先写 R2，再事务写入内容记录；记录写入失败时尝试移除对象。文件只通过受保护接口访问，相册仅内联显示校验过文件头的光栅图片。其他类型强制附件下载，所有下载禁止缓存。

## 分页与查询

记录以 pinned DESC, updated_at DESC, id DESC 稳定排序，游标包含 [0或1, 更新时间, ID] 三个值，并校验类型。每页 200 条，使用第 201 条判断是否有更多结果。通过 SQL 参数绑定处理搜索、标签、状态、专题、项目、月份、阅读状态和游标输入。筛选总数在应用游标前独立聚合，不依赖客户端已加载的页数。

主页的最近编辑、置顶、活跃待办与近期日程分别查询，避免被主列表的分页或置顶顺序截断。日程按客户端传入的本地日期筛选，格式无效时回退到 UTC 当天。切换模块或筛选时，客户端核对响应所属查询，避免把上一页的记录短暂显示在新模块。

JSON 导出使用分页读取全部正常/归档及回收站记录，附带专题和设置，格式为 inner-space-v2。导入先校验，再创建专题、项目和其他文字记录，映射新旧 ID；兼容 inner-space-v1。导入是追加操作，失败后不回滚已创建内容；界面报告进度及完成数量。v2 JSON 不包含附件二进制、版本和审计。v3 ZIP 进一步包含原文件、SHA-256 清单和历史/操作记录归档；恢复内容和附件，归档历史不回写。

## 部署和后续扩展

发布复用原有 Sites 站点并保留其当前受众范围，按平台返回的状态选择发布接口；不把页面文案当作访问控制。`worker/index.ts` 保留 starter 的连接器上下文封装，并给 HTML/JSON 设置私密禁缓存与基本安全头。本版没有启用连接器或外部 AI 服务。

0001 迁移增加 collections 表、pinned 与 collection_id，后者采用 ON DELETE SET NULL；原有记录默认不置顶、不关联专题。迁移不重建或清空原 records 表。线上发布由平台应用受版本管理的迁移，本地测试只操作 .wrangler/state。

后续若需要自动备份、后台提醒、端到端加密、全文索引、多因素认证或大批量文件夹管理，应分别建立业务约束、任务执行和验收方案，不能仅增加一个界面开关就宣称已支持。

## 0.3.0 补充

默认列表使用置顶、更新时间、ID 游标。其他排序把对应 SQL 排序值放入相同的三元游标，标题和日期用升序比较，ID 始终用降序打破相等。lite 请求只读取列表和总数；主页汇总与账本聚合不在翻页请求重复执行。日历独立读取可见六周范围的所有分页。

草稿表与正式内容分离，编辑器停止输入后保存；草稿本身也使用版本条件写入。正式记录保存成功后清理同版本草稿，不删除其他窗口的新草稿。附件通过 meta.parentId 关联授权内容，原始对象键始终由服务端生成并保留。备份恢复先创建所有目标，再恢复它们的回收站状态，避免已删除项目和笔记阻断关联恢复。

上传在 INSERT 的数据库条件中检查总记录数与附件总量，避免并发请求先检查后写入超额。元数据写入失败后尝试清理新对象。空间用量按已登记元数据统计，含回收站，不代表云厂商实时账单。正常写入执行历史与操作日志保留策略。

HTML 首屏在身份校验后读取同账户偏好；不依赖浏览器缓存猜测主题。平台身份头的可信前提、CSP 与托管边界见 README 和 REVIEW.md。

## 0.4.0 状态与上传

useSpaceData 统一维护请求代次、游标、查询键与保守的局部更新规则；modal/selection/undo 由纯 reducer 管理，卡片操作通过 actions 合约传入。筛选键变更后仍隐藏旧响应，延迟写入完成时刷新当前路由。

上传队列控制器与 React 展示分离，所有传输顺序执行；只有 queued/uploading 全部结束才发出一个完成事件，新增任务并入同一轮，失败项重试不重复发送成功项。文件库和编辑器附件共用同一控制器与组件。取消或断网不能保证服务端尚未接收，界面提示刷新核对未确认结果。

主题由账户偏好在 SSR 阶段写入 Workspace 和 HTML data-theme。共享偏好读取采用 React 请求缓存，不使用跨用户的模块级缓存。

部署必须保证身份头只由可信 Sites 网关注入、外部伪造头被清除、无可绕过网关的直连入口；本仓库不具备独立确认托管端 workers.dev 开关的能力，不能把该信任前提当作已核实的配置。

## 0.5.0 并发、导出与清理

草稿关闭操作以保存/删除请求的实际返回值决定是否关闭，不依赖异步 React 状态快照。丢弃先设置停止标志、取消延时任务、等待在途保存，再删除最终草稿版本，避免删后重建；删除冲突保留当前窗口。附件队列向编辑器报告运行状态，退出确认包含未完成上传说明。

偏好 reducer 分别保存基准、表单、最新远端值。未脏时同步，已脏时保留输入并要求显式载入或合并；合并只覆盖本窗口改过的字段。PUT 比较规范化 expectedPreferences，并用数据库原始 value 条件更新/插入，阻断检查与提交之间的竞争。旧客户端可不带基准；当前前端始终带上。新增保留期存于 settings JSON，无需数据库迁移，旧设置缺省为 0。

lite 列表仍为列表和总数两次查询；传 project 时补一次只针对该账户和项目的待办聚合，完成数不受首屏 200 条限制。命令面板使用受保护的 lite 搜索，250 毫秒去抖、取消旧请求、方向键与 Enter 导航，不引入第三方命令库。

专题导出复用同一备份生成器，collection + includeAttachments 读取专题记录及其关联附件，父记录查询同样绑定 owner。归档接口按该专题当前记录及附件限定历史/操作日志；全量备份原语义不变。专题包不输出整个账户的偏好。

用户主动选择 30/90 天并保存后，内容 POST/PATCH 或上传成功才触发有界清理，读请求和设置保存均不清理。每批最多 20 条，正式恢复先写入，再检查其他到期项。手动与自动删除共用事务构造器：版本、owner、deleted_at 条件保护草稿/历史移除、审计和记录删除，文件键通过同一事务写入 blob_cleanup。自动清理的每条 SQL 还核对设置原值和截止时间，防止并发关闭保留期后仍按旧设置删数据。异常仅记录私密服务日志，不把已完成的前台保存报告为失败；后续写入与附件清理入口可继续处理。开启保留期时客户端总是刷新聚合，不使用只替换一行的优化。

Worker 入口显式拒绝 workers.dev（含子域名、端口、尾点变体），源配置设置 workers_dev=false、preview_urls=false；此声明和应用拒绝策略不证明托管平台最终配置或其他自定义入口已经核验。Sites 身份集成保留，不自行发明签名协议或更改受众范围。

## 0.6.0 个人日期、收集与正文图片

生日使用 contact.meta.birthday（MM-DD），提醒事件使用 event.meta.reminderType（countdown/subscription）。记录边界验证日期类型。普通完整空间请求增加一次仅返回 ID、标题、日期及必要 meta 的 owner 聚合查询，不受首屏 200 条限制；lite 不包含该查询。纯日期函数以日历日期的 UTC 零点做天数相减，避免设备夏令时影响差一天；当天仍按客户端本地日期提示决定。生日平年 02-29 明确映射到 02-28，最多显示 8 项。没有创建后台通知或财务写入路径。

快捷入口的公开页面仅接收当前浏览器的片段参数，使用可选登录状态和正常平台登录链接保留返回路径，不读取私人记录。带入前必须确认，参数大小、种类和 HTTP/HTTPS 地址独立校验；确认后编辑器采用 new-kind-UUID 草稿键并使用空白内容作基准，确保未再次改动的预填内容也能保留为草稿。设置里的恢复入口传回原草稿键，正式内容保存成功再清理草稿。

图片粘贴仅处理用户主动 paste 事件的图片文件，不读取整个系统剪贴板或网页正文。队列保存上传返回的记录并仅报告一次插入，失败重试不重复插入已成功图片。正文仅渲染完全匹配受保护 UUID 路径的图片，外部图片和活动协议仍当文字处理；下载服务继续验证 owner、文件键、软删除状态和图片 MIME。未保存笔记粘贴的图片先存在相册中，草稿仅保存 URL 引用，不存 Base64 或 Blob 对象。

专题导出遍历正文受保护引用，补充同账户图片记录及字节，大小/哈希检查保持；恢复分两阶段映射 ID，之后才回写正文并恢复回收站状态，避免版本号和图片地址过期。纯 JSON 缺少图片字节时将无法恢复的引用改为说明文字，避免错误引用原数据。历史和活动归档不回写。

React.lazy/Suspense 分割重模块，备份库在导出按钮操作时动态导入；模块加载有可见状态和原有页面错误边界。未新增依赖、数据迁移、调度、外部集成或访问范围变更。
