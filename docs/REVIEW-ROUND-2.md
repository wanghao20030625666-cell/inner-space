## 需要更正的审查结论

1. **日历有数据来源。** calendar.tsx 的 effect 调用 allRecords()，按 from/to 获取可见六周范围的全部分页，并非没有 fetch。操作记录在 activity-list.tsx 中独立使用 /api/activity 的游标分页。此轮保留这些实现。
2. **0.3.0 已有主题 SSR。** page.tsx 会读取当前账户偏好并把 initialPreferences 传给 Workspace。本轮进一步让 layout.tsx 在 HTML 根节点输出 data-theme，并以 React 请求缓存复用偏好读取；客户端主题保存同步根节点。无需增加可能与当前账户偏好不一致的镜像 Cookie。HTTP 集成测试实际检查 dark HTML 与 workspace dark 同时存在。
3. **D1 不是“每批最多 100 语句”。** [Cloudflare 当前限制说明](https://developers.cloudflare.com/d1/platform/limits/)区分每条查询的绑定参数上限与 batch；batch 的单条语句仍受独立限制，整个 batch 按一次调用计入查询配额。50 条记录是本项目为延迟、负载与冲突重试选择的应用批量大小，不是平台宣称的硬上限。

## 保留为后续专项的建议

- **身份信任边界：**仍依赖 Sites 网关验证并注入身份、阻止绕过网关的入口。仓库和现有 Sites 接口无法独立证明平台控制的 workers.dev 直连已关闭。README/ARCHITECTURE 保留该前提，不伪造应用层签名检查，也不宣称平台风险已消除。
- **FTS5：**[D1 支持 FTS5](https://developers.cloudflare.com/d1/sql-api/sql-statements/)，但是否切换需先测量实际数据、短中文词和子串语义，并核实所选 tokenizer。在没有性能基准的情况下不承诺“快一个量级”，本轮没有改变搜索语义或增加索引迁移。
- **回收站自动清空：**会改变不可逆的数据保留行为，应先确定是否启用、保留时间及确认流程。本轮保留手动恢复和受确认的彻底删除。
- **iCal 订阅：**涉及向外部日历客户端提供持续读取凭据，需要设计令牌作用域、撤销和访问记录。本轮保留受登录保护的 ICS 下载。
- **定时备份与缩略图：**需要托管端的定时触发、独立备份存储/保留策略或图像处理能力，不能靠前端开关宣称支持。
- **收藏抓标题与周期待办：**分别涉及完整 SSRF 防护、幂等的重复实例状态机，应单独实现和验证。

本轮没有自动删除线上内容、创建订阅令牌、改变访问范围或添加后台定时任务。所有演示和验收数据只在本地。
